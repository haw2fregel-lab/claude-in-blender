# パラメータを常設して触り続ける

## 使う時

「〜のジェネレーター作って」「数値を後から触りたい」と言われた時に、**形をゼロから作る**（円盤・リング・螺旋・星型）。**処理はこちらが書き、値はユーザーが握り続ける。** 何度も往復して詰めたい時の形。

隣の形が2つ——一発で決めて終わる操作は Skill `blender-quick-edit`。**既にあるメッシュ**へ変形を掛け続けるのは Skill `blender-modifier-inject`。

**作りたい1個専用に組む**——露出するのはユーザーが仕上げで触ると言ったものだけ。次の要求は、新しく1本組む。種類を足すたびに分岐とパラメータが積もり、作業中に関係ない項目が画面を埋める。

## 置き場を先に決める

**置き場は作る前に聞く**——作った時点で、もう資産だから。「試すだけ？ 残す？」の一言でよい。使い捨て（一時ディレクトリ）なら**閉じると消えることを言葉にして合意を取る**。永続なら、置き場はユーザーが決める。迷うなら使い捨てで始めてよい。ただし:

**使い捨てで始めたものをユーザーが調整し始めたら、その時点で資産。** 「まだ試してるだけ」のうちに本番の形になっている——そこを見張るのはこちらの仕事。調整が続いたら区切りで永続化を提案し、決まった数値は消える前に読み出して残す。

## 組み立て

**1ファイル完結**・75 行前後——受け取った人がそのまま実行するだけで動く形を保つ。差し替わるのは形の式だけ、残りは定型:

- **`PropertyGroup`** に露出パラメータを定義し、`bpy.types.Object` へ `PointerProperty` でぶら下げる。全プロパティの `update=` に共通コールバック（→再生成関数）——**代入だけで発火する**
- **`build(p)`**——頂点と面のリストを返す形の式。`bpy` から切り離して書くと、期待値の計算（扇なら `verts = 1 + segments`）がそのまま書ける
- **再生成関数**——`mesh.clear_geometry()` → `from_pydata()` → `update()`。**UV・頂点カラーは clear で消えるので毎回作り直す**。実行するのはオブジェクトモードの時だけ——編集モード中は先頭で return して待つ
- **`Panel`**——`Props.__annotations__` を回して `layout.prop()`。**パラメータを足せばパネルに自動で並ぶ**。編集モード中は `box().alert` で「反映されません」の警告。検算値は custom prop（`p["_info"]`）に入れて表示——prop 定義の外なので update は再発火しない
- **登録と対象**——再実行に備え unregister → register。オブジェクトは `bpy.data.objects.get(名前)` で再利用、無ければ `bpy.data` で作って link。選択操作は `bpy.context.view_layer.objects` を回す（select は view layer 内の object のみ）

ユーザーへは**サイドパネル（N キー）の「Tool」タブにパネルが出て、数値を動かすと形がその場で変わる**と伝える。

## 育て方

骨のまま始めて、要求が出たところだけ足す。

| 欲しくなったもの | やること |
| --- | --- |
| パラメータ追加 | `Props` に1行。パネルは自動 |
| 幅・高さ方向の分割 | `build` を周×幅のグリッドに。**UV の v が連続してカーブが効くようになる** |
| UV の分布を曲げる・色を乗せる | `CurveMapping` / `ColorRamp`（下記） |
| 手動で作り直すボタン | `Operator` を1つ、**パネルに `layout.operator()` で出す**（調整パネルはボタン経由の実行で出る）。中で `bpy.ops.object.mode_set` を往復すれば編集モードでも通る |
| 形や操作を選びたい | 別のパネルを1本組む |

`CurveMapping` と `ColorRamp` は **ID を器に借りて持つ**（直接持てるのは ID だけ）。カーブは `ShaderNodeTree` に `ShaderNodeFloatCurve` ノードを作り `nd.mapping` を使う（**evaluate 前に `mapping.update()` 必須**）。ランプはレガシーテクスチャ `bpy.data.textures.new(名前, 'NONE')` の `use_color_ramp = True` → `color_ramp.evaluate(t)`。パネルへは `layout.template_curve_mapping(nd, "mapping")` / `template_color_ramp(tex, "color_ramp", expand=True)`——RNA 関数なので `bl_rna.functions` 側に載る。**カーブが効くのは対象の値が連続している時**——幅方向の分割を 2 以上にして UV の v を連続にする（分割 1 の v は 0/1 の2値で、端点を通るカーブは素通りする）。頂点カラーは `mesh.color_attributes.new(name, type='FLOAT_COLOR', domain='POINT')`。

## 渡す前に接続テスト（必須）

パラメータを足したら**値を2点振って、結果の数値が動くことを確認する**——効いている証拠は数値の動きだけ（扇の分割 32→64 なら verts 33→65、と期待値と比べる）。分布を変えるパラメータは**平均や件数で測る**——min/max は同じまま中身が動く。検算はヘッドレス（`--background --factory-startup --python`）でも回る。

## 罠

| 罠 | 症状 | 対処 |
| --- | --- | --- |
| 編集モードで `from_pydata` | `RuntimeError: Cannot add vertices in edit mode` | 先頭でモードを見て止め、パネルに理由を出す |
| `update` から `bpy.ops` | 不安定・再帰の危険 | `bpy.ops` は `Operator` の中から呼ぶ |
| `clear_geometry()` | UV と頂点カラーが消える | 詰め直した後に毎回作り直す（loop 数が変わるため） |
| `atan2` から UV の u | 一周の継ぎ目で 1.0 → 0 に飛び、その面だけ絵が全幅を逆走する | 面のインデックスから出す |
| カーブのオーバーシュート | UV が 1.0 を超えてテクスチャがラップする | AUTO ハンドルの性質。端の傾きを見る |
| `dimensions` で検算 | 変形したのに値が変わらない | depsgraph 待ち。**頂点座標から直接計算する** |
| `dir()` / `bl_rna.properties` で API 確認 | 実在するものが「無い」と出る | RNA 関数は `bl_rna.functions`、Operator の prop は `get_rna_type().properties` |
| クラス名 | `does not contain '_PT_'` 警告 | `PREFIX_PT_name` / `PREFIX_OT_name` にする |

## 境界

- **手編集は作り直しで消える。** 「パラメータで寄せきってから手で仕上げる」順をユーザーに伝える
- **ファイルの保存・書き出しは印鑑を待つ。** メッシュを作るところまでがこの形の範囲
- 頂点数が予算内か確認する。分割は二次で増える（周 32 × 幅 4 で 256 三角）
